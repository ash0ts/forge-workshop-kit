# Workshop visual guides

These are the authored illustrations for the six current workshops. Each workshop contains a system overview, six explanations, and a poster. They use the portable `teenage-engineering-visualizations` skill; no other visual skill supplies their design.

Start with [index.json](index.json). It maps each explanation to the current notebook step, actual exercise and cell identities, code function, control, and deck concept. Editing an illustration does not change an experiment or its saved results.

## Edit an explanation

Edit the JSON specification for the title, explanation, source links, and stable reveal identities. Each state's `artwork` points to an original SVG generated by `scripts/illustrate_<workshop>.py`; edit that script to change the drawing or its displayed code. Routing shares drawing primitives with Airline, and Solar shares them with Inspection, so retain all six scripts when working outside the repository. Keep an intermediate value consistent across all states and output formats. Code excerpts are shortened for the figure; full editable functions remain in the notebook and are linked from the source list.

Every specification labels its provenance. An illustrative mechanism can describe implemented behavior without claiming that a learner has executed it. Recorded comparisons belong to instructor executions, and final examples must not enter development prompts. No display interaction starts inference, training, or publication.

The original `hero.svg` drawings establish the situation: a desk and checked account, a solar observation and experiment, a routed message, a PCB inspection station, an integrated departure board, or a preserved return itinerary. Illustrative values are labeled. Solar observations, recorded predictions, and inspection photographs retain their data identities and scales. The illustrators read bundled inputs only; they do not train a model or contact a provider.

Six explanations include a `native_capture`. Its numbered outlines identify fields in an actual Forge screenshot, with the same numbers attached to the relevant code or operation. The original PNG and native source URL remain available. These captures predate this revision; their capture timestamps were not recorded, so the metadata leaves that date unavailable rather than inventing one.

## Reuse and sources

Source links in each JSON file point to the implementation and the public worked example. [media/sources.json](media/sources.json) records copied asset paths, source URLs, and SHA-256 checksums. PCB photographs come from VisA under CC BY 4.0; preserve that attribution with exported figures. The Solar panels are existing Workshop Kit diagrams grounded in the documented GOES and AIA observations.

Poster destinations use the stable workshop anchors in the public library. Each anchor leads to the current Report, notebook, and deck; a QR code must not point directly to a private execution.

## Regenerate the visuals

From the Workshop Kit checkout, use the existing build command:

```sh
uv run python scripts/build_visual_guides.py --exports
```

It regenerates artwork, notebook and slide frames, posters, the reference gallery, and downloadable source. It makes no inference, training, or publication calls. PNG, PDF, and QR exports need the skill's pinned Node dependencies and Chromium; install those using the instructions in `skills/teenage-engineering-visualizations/README.md`.

The `workshop-visual-source.zip` download contains `visual-guides/`, all six illustrator scripts, and the complete skill, including fonts, tokens, the renderer, and its dependency lockfile. It does not contain the Workshop Kit runtime or repository build command. From the extracted directory, regenerate the artwork with Python 3.11 or later:

```sh
for workshop in pending solar routing inspection transit airline; do
  python scripts/illustrate_${workshop}.py
done
```

Render a sequence and inspect its actual text bounds:

```sh
python skills/teenage-engineering-visualizations/scripts/render.py visual-guides/routing/features.json --output exports/routing-features --layout slide --formats svg,html,png,pdf
python skills/teenage-engineering-visualizations/scripts/validate.py exports/routing-features --browser
```

Use `--layout notebook` for a notebook panel, `--layout digital` for a poster PNG, and `--layout print` for its A2 PDF. Poster specifications are named `poster.json`. SVG and HTML sequences work with Python alone; poster QR codes and PNG/PDF exports use Node and Chromium. The complete figure list is in `index.json`.

Fix the specification, illustrator, or shared renderer, then regenerate. Do not repair a generated SVG or image alone.
