# Ten-minute workshop walkthrough

The walkthrough follows six practical problems through participant code and saved Forge records. It assumes the viewer has not heard about the workshops. The recording is silent so you can add your own voice-over.

Use the [timed narration script](../media/walkthrough/narration.md) when dubbing. The [production guide](../media/walkthrough/README.md) explains the clean and captioned MP4s, subtitles, source captures, and editing instructions. [edit.json](../media/walkthrough/edit.json) is the source of truth for narration and timing.

| Time | Show | Explain |
| --- | --- | --- |
| 0:00–0:50 | Public library and one Report | Why working demos still need investigation and evaluation |
| 0:50–1:30 | Notebook start page and running guide | Save the notebook, launch locally, check access, then execute explicitly |
| 1:30–2:25 | Pending tool handoff and Agent Lens | Inspect an action and check its account outcome |
| 2:25–3:25 | Solar forecast window, run, and files | Compare research changes and reproduce a forecast |
| 3:25–4:20 | Routing mapping drill and evaluations | Separate model quality from release correctness |
| 4:20–5:15 | PCB patch calculation and photographs | Examine misses, false alarms, and review budgets |
| 5:15–6:10 | Transit claims and R5 comparisons | Check ownership, integration, and whether memory helped |
| 6:10–7:10 | Airline itinerary and conversation | Turn reviewed behavior into monitoring and regression cases |
| 7:10–8:00 | Direct ARIA controls and saved conversation | Ask a focused question, then verify a cited claim |
| 8:00–9:20 | Running guide, entry links, and library | Use the materials and distinguish visits from participant progress |
| 9:20–10:00 | Workshop selection and notebook | Choose one relevant problem and try an exercise |

The product clips show saved executions. Guide interactions change the explanation on screen; they do not run experiments. Native captures omit the signed-in account header. Captions remain below the screen so the viewer can inspect values and controls.

## Share with the recording

Suggested description:

> These six workshops use a refund, a solar forecast, a support request, a defective circuit board, a departure board, and a changed booking to teach practical Forge workflows. The tour shows the code participants change and the records they use to check it. Read one example, use a short demo, or try an exercise in your own project. Full sessions remain technical previews.

For external video viewers, use **https://utm.io/uuIan**. For external community Slack, use **https://utm.io/uuIaS**. Colleague reviews use the direct [library address](https://ash0ts.github.io/forge-workshop-kit/).

The [tracking guide](share-links.md) owns the tags and placement rules. Visits identify entry paths; they do not prove that someone copied a notebook or finished an exercise. Keep [current readiness](../next-up.md) available beside the recording.

After adding a voice-over, check caption timing and public viewing permissions before replacing the local recording link with a hosted Loom URL.
