# Forge Workshop Kit: narration for the ten-minute tour

Read this over the clean video. The captioned version uses these same words. The recording shows saved work and display-only interactions; it is not a new live experiment.

## 00:00:00–00:00:50 · Why these workshops exist

**00:00:00–00:00:25 — Show:** The six workshop cards.

We built these workshops for engineers who want to understand the work around an AI application after its first demo succeeds. A refund agent can finish an API call and leave the account wrong. A forecast can have a score nobody can reproduce. Two coding agents can finish assignments whose parts disagree.

**00:00:25–00:00:39 — Show:** The published Report introduction.

The Reports introduce each problem through a worked example, with code and recorded results. You can read the explanation first, then try the same exercise in your own project.

**00:00:39–00:00:50 — Show:** The complete account comparison in the published Report.

The customer needs one duplicate payment refunded. The account comparison shows whether the agent changed only that payment.

## 00:00:50–00:01:30 · How someone starts

**00:00:50–00:01:15 — Show:** The public notebook start page and setup instructions.

Each start page links the Forge template, the current notebook download, and laptop instructions. Copy the template into your own project and check access. Use the download if hosted notebooks are unavailable to your account. Your inference allowance starts at eight dollars; compute and ARIA usage are separate.

**00:01:15–00:01:30 — Show:** The running guide.

The running guide covers demos and full sessions. Code, free checks, run buttons, and results stay together. Opening saved work starts no training or inference.

## 00:01:30–00:02:25 · Pending: inspect and change an agent

**00:01:30–00:01:53 — Show:** The invoice dispatch and observation sequence.

Pending handles office billing and account access. A customer needs a duplicate charge refunded. Participants write an invoice tool, dispatch an action, and append its returned observation to the next model request. The drawing follows that invoice through each operation.

**00:01:53–00:02:25 — Show:** Actual arguments and returned account data.

In Agent Lens, inspect the actual arguments, returned result, timing, and next action. The account check tests the customer outcome. A committed write can lose its response. Reusing the operation ID prevents a duplicate membership. Participants compare manual and agent-written harness changes on matching cases. The recorded final pass count tied, despite different tool behavior.

## 00:02:25–00:03:25 · Solar: test a research change

**00:02:25–00:02:48 — Show:** One forecast window and its target.

Solar is a lab preparing its weekly forecast review with real GOES measurements and AIA images. Follow one timestamp through the history window and separate future target. Persistence copies the latest reading forward, giving each trained model a baseline to beat.

**00:02:48–00:03:10 — Show:** Six configurations, validation error and runtime.

Train small models and inspect their loss curves. A Sweep compares six existing configurations. Then a research agent proposes image-model edits. Review the diffs, train candidates, and compare. The language model stays fixed while forecasting weights train.

**00:03:10–00:03:25 — Show:** The exact source saved with the selected Solar image model.

Artifacts preserve the tested source, settings, weights, and predictions. The unsuccessful GOES recipe and mixed image results stay visible, so participants can investigate both.

## 00:03:25–00:04:20 · Routing: train, release and recover

**00:03:25–00:03:55 — Show:** The same probability columns with different intent mappings.

Routing follows a banking support queue. A missing card needs a different workflow from a card that does not work. This controlled release defect reorders intent names without moving probability columns. A confident score now selects the wrong queue. Participants write a regression check, repair the loader, and restore a previous version. The classifier itself has not changed.

**00:03:55–00:04:20 — Show:** Matching requests and evaluated predictions.

Using Banking77, fit a baseline, inspect validation mistakes, and test another text representation. EvalTables aligns requests, predictions, labels, and errors across versions. Runs compare models. Artifacts preserve preprocessing, intent order, and the classifier. The release is a notebook batch predictor.

## 00:04:20–00:05:15 · Inspection: investigate a missed defect

**00:04:20–00:04:50 — Show:** One patch and its normal reference.

Inspection checks circuit boards before shipping, using real VisA photographs. Investigate a missed defect before replacing whole-image features with local patches. This calculation finds one patch's closest normal reference. Its distance becomes a feature, not a causal explanation. Supplied defect masks help inspection, but never enter the classifier.

**00:04:50–00:05:15 — Show:** Actual board images, scores and labels.

EvalTables shows boards beside scores and labels. Inspect a recovered miss and a new mistake, then compare active and random review with equal labeling budgets. Artifacts retain the feature code, reference bank, classifier, and threshold. More labels helping does not establish a better selection method.

## 00:05:15–00:06:10 · Transit: coordinate two coding workers

**00:05:15–00:05:40 — Show:** The claim race and atomic repair.

Transit uses two coding agents to build a departure board from a historical MBTA schedule. Implement dependencies, atomic claims, ownership, and integration. Two workers must not claim the same task. Submitted, tested, and integrated are separate states. Finished assignments still need combined application checks.

**00:05:40–00:06:10 — Show:** Matching solo and team acceptance cases.

On matching cases, the team failed two checks that the solo build passed. Twenty-four-oh-eight belongs to the original service day, making integration concrete. Agent Lens records edits, tests, and handoffs; Artifacts preserve releases. Fresh workers then run with and without a verified lesson. The recorded memory comparison found no advantage.

## 00:06:10–00:07:10 · Airline: connect monitoring to evaluations

**00:06:10–00:06:34 — Show:** Original, incomplete and preserved itineraries.

Airline follows a passenger changing part of a round trip, using simulated benchmark bookings. The API replaces the whole itinerary. Sending only the changed outbound flight can remove the return. Compare the original, incomplete, and preserved itineraries. A successful API call can leave the booking wrong.

**00:06:34–00:07:10 — Show:** A recoverable tool timeout and the passenger request.

Inspect this recoverable timeout, then review the turn before calibrating a tag. Agent Lens covers Conversations, Insights, Tags, and Alignment. Reviewed incidents become regression cases, and EvalTables compares repairs. Monitor agreement and agent correctness remain separate. The recorded agent passed; the itinerary defect is controlled. Native Alignment and prepared Insights still need qualification. Missing judgments remain unavailable.

## 00:07:10–00:08:00 · ARIA: investigate a result, then verify a claim

**00:07:10–00:07:30 — Show:** The actual shared ARIA controls with a restored response.

Explain a result before asking ARIA. Start ARIA investigation sends your question and selected records. The notebook saves the conversation. Check ARIA response retrieves the answer. Opening the notebook sends nothing.

**00:07:30–00:07:48 — Show:** The actual ARIA answer to a development question.

Open ARIA conversation continues the discussion in Forge. Check what the records support. ARIA neither scores results nor approves repairs. Organization settings govern its usage, outside the notebook allowance.

**00:07:48–00:08:00 — Show:** The cited execution artifact opened from the answer.

Open one cited record. Mark the claim supported, disputed, or unresolved. The recorded fallback teaches the same check.

## 00:08:00–00:09:20 · Use the material and measure the entry path
